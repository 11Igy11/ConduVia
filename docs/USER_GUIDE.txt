VIANYQUIST - KORISNICKE UPUTE
Beta verzija


1. Sto je ViaNyquist
--------------------

ViaNyquist je aplikacija za pregled i analizu mreznog prometa u predmetu/projektu.
Aplikacija pomaze korisniku da ucita JSON datasetove i PCAP datoteke, pregleda
komunikacijske tokove, izdvoji nalaze, vodi biljeske i izgradi profil aktivnosti
uredaja kroz predmet.

ViaNyquist ne dekriptira promet. Ako je promet kriptiran, aplikacija moze prikazati
metapodatke kao sto su IP adrese, portovi, protokoli, DNS upiti, TLS SNI nazivi,
vrijeme komunikacije i volumen prometa. To su istrazni indikatori, a ne dokaz
sadrzaja poruke ili razgovora.


2. Osnovni radni tijek
----------------------

Preporuceni tijek rada je:

1. Kreirati ili otvoriti projekt.
2. Postaviti WorkSpace folder projekta.
3. Unijeti poznate podatke o osobi/uredaju na koji se predmet odnosi.
4. Ucitati JSON dataset ili PCAP datoteku.
5. Pregledati tokove, metapodatke, artefakte i komunikacijske indikatore.
6. Oznaciti bitne stavke kao Findings.
7. Dodati vazne zakljucke u Notes.
8. Pregledati Profile za siru sliku aktivnosti kroz predmet.
9. Izvesti izvjestaje u WorkSpace folder.


3. Projekti
-----------

Projekt je osnovna jedinica rada. Sve sto se ucita, spremi ili zakljuci treba biti
vezano uz aktivni projekt.

Na stranici Projects korisnik moze:

- kreirati novi projekt
- otvoriti postojeci projekt
- urediti podatke projekta
- otvoriti JSON ili PCAP dataset
- pregledati nedavne JSON datasetove
- pregledati nedavne PCAP datasetove
- pregledati nedavnu aktivnost u projektu

Projekt treba imati WorkSpace folder. Bez WorkSpace foldera nije preporuceno ucitavati
datasetove jer aplikacija tada nema jasno mjesto za spremanje izvjestaja, biljeski
i pomocnih datoteka.


4. Podaci o osobi / uredaju
---------------------------

Kod kreiranja ili uredivanja projekta moguce je unijeti poznate podatke:

- ime
- prezime
- OIB
- broj mobitela / MSISDN
- IMSI
- IMEI
- poznata IP adresa
- dodatni identifikatori ili napomene

Ti podaci sluze kao "srce istine" projekta. Aplikacija ih koristi kako bi korisnika
upozorila ako ucitani dataset ili PCAP ne izgleda kao da pripada istom targetu.

Ako OIB nije ispravan, aplikacija treba upozoriti korisnika. OIB mora imati 11 znamenaka
i ispravan kontrolni broj.


5. WorkSpace folder
-------------------

WorkSpace folder je radni folder projekta. U njemu se spremaju pomocne datoteke,
biljeske i exporti.

Tipicna struktura WorkSpace foldera:

- datasets/
- exports/
- findings/
- notes/
- reports/

U folderu se nalazi i oznaka:

.vianyquist-workspace

Exporti se po defaultu spremaju u:

exports/

Biljeske projekta se dodatno spremaju u:

notes/project_notes.txt


6. JSON modul
-------------

JSON modul sluzi za rad s JSON datasetovima mreznih tokova.

U JSON modulu postoje podstranice:

- Explore
- Registry
- Listing

Explore prikazuje tokove i detalje o odabranom flowu. Korisnik moze pretrazivati,
filtrirati, gledati detalje i oznaciti flow kao Finding.

Registry daje siri pregled dataseta: broj tokova, aplikacije, protokole, IP adrese,
volumen prometa i ostale indikatore.

Listing sluzi za pregled odabranih kolona i export u tablicni oblik.

JSON dataset treba ucitati samo kada je odabran projekt. Ako dataset ima target
identifier ili target type koji se ne poklapa s projektom, korisnik treba provjeriti
radi li se o pogresnom datasetu.


7. PCAP modul
-------------

PCAP modul sluzi za ucitavanje i analizu PCAP/PCAPNG datoteka.

PCAP stranica ima vise pogleda:

- Summary
- Communications
- Evidence
- Network
- AI Summary

Summary daje pregled PCAP datoteke: trajanje, broj paketa, volumen, vidljive servise,
aktivnost po vremenu i omjer vidljivih/kriptiranih indikatora.

Communications prikazuje komunikacijske indikatore. Aplikacija moze prepoznati
messaging/push-like indikatore i moguce call/media indikatore, ali to radi iz
metapodataka. To nije dokaz da je poruka poslana ili poziv obavljen.

Evidence prikazuje vidljive metapodatke i citljive uzorke:

- DNS upite
- TLS SNI hostove
- HTTP hostove
- vidljive payload/metadata uzorke

Artifacts prikazuje izdvojene artefakte, npr. web tragove, lokalne mrezne indikatore,
moguce credentiale ako su vidljivi u plaintextu, Windows/enterprise hintove i slicno.

Network prikazuje protokole, top endpointove, portove i konekcije.

PCAP ne moze prikazati sadrzaj kriptiranog HTTPS, QUIC ili aplikacijskog prometa.
Ako nema plaintexta, prikazuju se samo metapodaci.


8. Findings
-----------

Finding je vazna stavka koju korisnik zeli izdvojiti iz dataseta ili PCAP analize.

Finding moze sadrzavati:

- naslov
- opis / napomenu
- status
- tagove
- source i destination IP/port
- protokol
- aplikaciju
- server name / host
- volumen i broj paketa

Findings treba koristiti za stvari koje su bitne za predmet, npr. neobicna komunikacija,
vazan vremenski period, zanimljiv host, sumnjiv ili vazan artefakt, ili komunikacija
koju treba dodatno provjeriti.


9. Notes
--------

Notes je prostor za slobodne biljeske po projektu.

U Notes se mogu zapisivati:

- radne napomene
- zakljucci
- pitanja za daljnju provjeru
- objasnjenja AI summaryja
- vazni PCAP ili JSON indikatori

Biljeske se spremaju uz projekt i dodatno se mogu zapisati u WorkSpace folder.


10. AI output
-------------

AI output je centralno mjesto za prikaz AI generiranih tekstova.

AI moze pomoci objasniti:

- JSON dataset
- pojedini flow
- finding
- PCAP analizu
- Activity Profile

AI tekst treba uvijek tretirati kao pomocno objasnjenje, a ne kao dokaz. Korisnik mora
provjeriti tvrdnje u stvarnim podacima prikazanim u aplikaciji.

AI ne smije izmisljati malware, prijetnje, identitet osobe ili sadrzaj komunikacije ako
to nije vidljivo u podacima.


11. Profile
-----------

Profile prikazuje profil aktivnosti kroz projekt.

Profile koristi podatke koji su spremljeni u projektu:

- JSON datasetove
- PCAP izvore
- Findings
- activity log
- poznate identifikatore projekta

Profile moze prikazati:

- broj JSON datasetova
- broj PCAP izvora
- broj Findingsa
- distribuciju IP adresa uredaja
- grupe servisa po volumenu
- domene po volumenu
- aktivnost po satu
- ritam aktivnosti

Profile se koristi za stvaranje sire slike o nacinu koristenja uredaja. Na primjer:
kada je uredaj najaktivniji, koji servisi se najvise koriste, koje domene se pojavljuju
i postoje li periodi smanjene aktivnosti.

Vazno: aktivnost uredaja nije isto sto i siguran dokaz da je osoba bila budna, spavala
ili osobno koristila uredaj. To su indikatori koje treba tumaciti oprezno.


12. Settings
------------

Settings sluzi za podesavanje aplikacije.

Trenutno se mogu podesiti:

- AI Base URL
- AI model
- AI timeout
- jezik AI tekstova i reporta
- tema aplikacije

Workflow aplikacije ostaje na engleskom jeziku. AI tekstovi i izvjestaji mogu biti
na hrvatskom ili engleskom, ovisno o postavci.


13. Export
----------

ViaNyquist podrzava export izvjestaja i tablica.

Exporti se po defaultu spremaju u WorkSpace folder aktivnog projekta, najcesce u:

exports/

Ovisno o modulu, moguci export formati su:

- HTML
- CSV
- Excel

HTML reporti su pogodni za citanje i dijeljenje. CSV i Excel su pogodni za daljnju
tablicnu obradu.


14. Refresh
-----------

Refresh treba osvjeziti prikaz aplikacije:

- projekte
- aktivni projekt
- recent JSON/PCAP liste
- activity log
- findings
- notes/profile prikaze
- settings prikaze

Ako korisnik primijeti da se prikaz nije osvjezio nakon spremanja ili ucitavanja, treba
koristiti Refresh.


15. Ogranicenja
---------------

ViaNyquist ima vazna ogranicenja:

- ne dekriptira HTTPS, QUIC ni aplikacijski promet
- ne dokazuje sadrzaj poruka ako sadrzaj nije vidljiv u plaintextu
- ne dokazuje identitet osobe koja je koristila uredaj
- ne dokazuje namjeru korisnika
- ne smije automatski zakljucivati da je komunikacija zlonamjerna
- PCAP komunikacijski indikatori su metapodaci i trebaju se tumaciti oprezno

Primjer:

Ako aplikacija prikaze WhatsApp hostove i promet prema portu 443, to znaci da je uredaj
komunicirao s WhatsApp povezanim servisima ili infrastrukturom. To ne znaci automatski
da znamo sadrzaj poruke ili tocnu radnju korisnika.


16. Preporucena praksa
----------------------

Za svaki predmet preporucuje se:

1. Uvijek raditi u aktivnom projektu.
2. Unijeti sto vise poznatih identifikatora.
3. Provjeriti upozorenja o nepodudaranju dataseta i projekta.
4. Spremiti bitne PCAP izvore u projekt.
5. Koristiti Findings za vazne stavke.
6. Koristiti Notes za radne zakljucke.
7. Koristiti Profile za siru sliku aktivnosti.
8. Exportirati izvjestaje u WorkSpace folder.
9. AI tekstove koristiti kao pomoc, a ne kao dokaz.


17. Kratki rjecnik
------------------

JSON dataset:
Datoteka ili folder s mreznim flow zapisima.

PCAP:
Packet capture datoteka koja sadrzi snimljene mrezne pakete.

Flow:
Komunikacijski tok izmedu izvora i odredista.

DNS:
Sustav koji prevodi nazive domena u IP adrese. DNS upit moze pokazati da je uredaj
trazio neku domenu.

TLS SNI:
Naziv servera koji se ponekad vidi tijekom uspostave TLS veze. Moze pokazati ciljanu
domenu, ali ne i sadrzaj komunikacije.

HTTP cleartext:
Nekriptirani HTTP promet. Ako postoji, moguce je vidjeti dijelove zahtjeva ili odgovora.

QUIC:
Moderni kriptirani transportni protokol, cesto preko UDP porta 443.

Finding:
Izdvojena vazna stavka u predmetu.

Activity Profile:
Pregled aktivnosti uredaja/projekta kroz spremljene datasetove, PCAP izvore i nalaze.

WorkSpace:
Radni folder projekta u koji se spremaju exporti, biljeske i pomocne datoteke.


18. Napomena za beta testiranje
-------------------------------

Ova verzija je beta verzija. Cilj testiranja je provjeriti:

- je li workflow razumljiv
- jesu li JSON i PCAP moduli dovoljno pregledni
- jesu li upozorenja oko projekta i targeta jasna
- spremaju li se exporti u ocekivani folder
- rade li Findings i Notes ocekivano
- daje li Profile korisnu sliku aktivnosti
- jesu li AI tekstovi korisni, razumljivi i dovoljno oprezni

Ako nesto izgleda nelogicno, nepregledno ili zbunjujuce, treba zapisati primjer,
screenshot i korake kako se do toga doslo.
